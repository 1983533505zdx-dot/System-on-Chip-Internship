# Simulation source notes

## tb_button_conditioner.v

- `dut` and `low_dut`: same filter, opposite physical input polarity; both must expose identical logical `pressed`.
- `cycles`: schedule stimulus at falling edges to avoid a testbench/design race at the sampling edge.
- `expect_state`: uses case inequality to also catch unknown X output values.
- Short raw transitions: bounce injection; expected no state change.
- `rises` and `falls`: count accepted output transitions, exactly one each.
- Final reset: confirms pressed returns inactive.

## tb_axi_gpio_irq.v

- Actual AXI GPIO v2.0 model generated by Vivado 2018.3. Not a hand-written GPIO substitute.
- `wr`: drives independent address/data valid channels and waits for both handshakes and B response.
- `rd`: performs AR and R handshakes; checks AXI response.
- Reset exceeds XSim global startup reset.
- Clear current IPISR status first, then enable IPIER and GIER.
- Reject bounce; confirm DATA and IPISR; IRQ must remain high until source clear.
- Held input after clear must not retrigger; release is another input-change event.
- IPIER masking blocks output; pending is delivered after enable is restored.
- Timeout plus `$fatal` checks make failures visible; final PASS indicates every check completed.

Neither testbench models the Cortex-A9, GIC, or C ISR. The board test provides that separate end-to-end evidence. Simulation threshold is 4, hardware threshold is 1,000,000 cycles.
